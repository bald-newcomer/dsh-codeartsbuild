## 1. 背景与目标

### 1.1 背景

华为云 **CodeArts Build（编译构建）** 是云上编译构建平台。开发者在 **DeepSeek Harness（dsh）** 中使用 AI 编码助手，但缺少与构建系统的集成——无法通过自然语言完成"本地编译验证 → 云端任务创建 → 执行构建 → 获取产物 → 失败诊断"的完整闭环。

### 1.2 目标

| 编号 | 目标 | 验收标准 |
|------|------|----------|
| G1 | 自动创建并执行构建 | 基于给定项目，自动本地构建验证，创建云端任务并**执行成功** |
| G2 | 异常自动诊断 | 构建失败自动拉取日志、清洗建模、LLM 分析根因，给出可操作建议并支持修复闭环 |
| G3 | 获取构建产物 | 列出产物清单，提供**下载链接**与**页面查询链接** |
| G4 | 构建状态监控 | 轮询等待构建进入终态（指数退避、超时返回 TIMEOUT） |
| G5 | 业务抽象 | 抽象构建生命周期核心域，以 **dsh 插件**承载 |

### 1.3 非目标（本期不做）

- 构建任务图形化编排界面
- 构建机（Slave）管理
- IAM 账号/权限管理
- 非 CodeArtsBuild 的 Provider 实现（预留扩展点）

## 3. 业务场景抽象

```
构建生命周期 (Build Lifecycle)
├── 场景 A: 项目感知       — list_projects / list_jobs / get_job
├── 场景 B: 本地构建       — repo_build（探测/指导/执行/产物/留档 单工具）
├── 场景 C: 任务编排       — create_job / update_job / delete_job / list_templates
├── 场景 D: 执行控制       — run_job / stop_job
├── 场景 E: 状态监控       — get_status / list_records / get_record / wait_build
├── 场景 F: 产物管理       — list_artifacts（下载+页面双链接）
└── 场景 G: 故障诊断       — get_log（清洗建模）+ 修复闭环（≤3 轮）
```

## 4. 功能需求

| 功能域 | 工具 | 说明 |
|--------|------|------|
| 本地构建 | `repo_build` | 仓库类型探测→编译指导→执行→产物→留档；编译过程模型自决 |
| 项目感知 | `list_projects` / `list_jobs` / `get_job` | 项目/任务查询 |
| 任务编排 | `create_job` / `update_job` / `delete_job` / `list_templates` | 任务 CRUD + 模板发现 |
| 执行控制 | `run_job` / `stop_job` | 触发/停止 |
| 状态监控 | `get_status` / `list_records` / `get_record` / `wait_build` | 状态查询/历史/轮询 |
| 产物/日志 | `list_artifacts` / `get_log` | 产物双链接 / 日志清洗 |

---

## 5. 非功能需求

| 类别 | 需求 | 指标 |
|------|------|------|
| 安全 | 凭据不外泄 | AK/SK 由 KooCLI 托管，插件不接触；工具结果不含敏感字段 |
| 安全 | 删除保护 | `delete_job` 不可逆，须用户确认 |
| 性能 | 列表分页 | 默认 20 条/页，上限 100 |
| 性能 | 大日志管控 | `get_log` 仅 error 时获取，截断标记 truncated |
| 可靠 | 网络重试 | 幂等 GET ≤3 次；wait_build 抖动 ≤2 次 |
| 可靠 | 修复闭环 | ≤3 轮，超限升级用户 |
| 可用 | 轮询超时 | 默认 30min，超时返回 TIMEOUT 非异常 |
| 可扩展 | Provider 可插拔 | 云端 `codeartsbuild/` + 本地 `local-build/` 双 Provider |
| 可观测 | 过程留档 | repo_build 自动留档 build-records/ |
