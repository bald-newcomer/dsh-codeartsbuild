# FE-05-华为云调用承载方案对比评审决策-20260920

> **文档编号**: CAB-FE-005
> **类型**: 独立迭代特性设计（架构评审决策）
> **日期**: 2026-09-20
> **状态**: 已决策

> **上游依赖**: 接口契约（`docs/api/api-contract.md` §1.2 通用约定）、FE-06-自建HTTP承载切换方案-20260920.md
> **关联特性**: FE-06（自建 HTTP 承载切换方案，实施计划）

## 1. 决策

**（2026-09-20）从华为云 SDK 业务客户端切换为自建 HTTP 调用（AK/SK 签名）**。

背景：SDK 业务客户端（`huaweicloud-sdk-codeartsbuild`）不可信——请求/响应处理黑盒（模型类字段不完整：`CreateBuildJobRequestBody` 缺 source_code/agency_urn/description）、内部行为无法控制（iam client 代理丢失需 monkey-patch）、类型强制转换掩盖真实请求结构。自建 HTTP 后请求体/响应解析完全透明、可控，契约即实现。

## 2. 方案对比

| 维度 | 华为云 SDK（v0.7.9 方案） | 自建 HTTP（新方案 ✅ 已决策） |
|------|---------------------------|------------------------------|
| 请求/响应透明性 | ❌ 黑盒：模型类序列化不可控，字段丢失难排查 | ✅ 完全透明：请求体/响应解析由插件代码直接构造，契约即实现 |
| 字段完整性 | ❌ `CreateBuildJobRequestBody` 缺 source_code/agency_urn/description | ✅ 全部契约字段按 api-contract.md 直传（含低频字段） |
| 依赖 | ⚠️ `huaweicloud-sdk-codeartsbuild` + sdk-core + uuid + moment + lodash | ✅ 仅保留 `huaweicloud-sdk-core`（AKSKSigner 签名），bundle 更小 |
| 代理支持 | ❌ iam client 不继承代理，需 monkey-patch（sdk-proxy-patch.ts） | ✅ HTTP 层显式处理代理（Node fetch + dispatcher），无补丁 |
| 认证 | AK/SK 签名（Signer） | AK/SK 签名（`AKSKSigner.sign()`，与 SDK 同源，无 IAM 依赖） |
| 类型安全 | ⚠️ `(client as any)[method]()` 无方法级校验 | ✅ 请求/响应类型由插件定义，编译期校验（方法级 dispatch 表） |
| 错误处理 | ⚠️ SDK 异常类型依赖构造名判断（脆） | ✅ 直接解析 HTTP 状态码 + 响应体，稳定可控 |
| 测试策略 | ⚠️ mock SDK 客户端 | ✅ mock fetch 层，可录制回放 |
| M4 多 Provider 演进 | ✅ 各后端官方 SDK | ⚠️ 各后端需自建 HTTP（接口文档驱动，但可控） |
| 已实测资产 | ⚠️ 需对 SDK 重新实测对齐 | ✅ 契约实调用确认结果直接复用（HTTP 与 KooCLI 同走 OpenAPI） |

## 3. 决策依据

SDK 业务客户端的黑盒行为（字段丢失、代理缺陷、类型强制转换）直接损害契约驱动原则；自建 HTTP 后请求/响应完全透明，契约即实现，低频字段不再丢失。签名算法与 SDK 同源（`AKSKSigner`），认证可靠性不变，且绕开 IAM token 依赖。

## 4. 代价与影响

- 推翻 v0.7.9 SDK 决策
- `sdk-client.ts` 需重构为 `http-client.ts`
- `credential-provider.ts` 返回 AK/SK 而非 BasicCredentials
- `sdk-proxy-patch.ts` 删除
- region→endpoint 映射表内嵌（不再依赖 SDK Region 类）
- 已写 create-job.ts 的 SDK 调用段需重构

实施步骤与回滚条件见 FE-06（http-migration-plan）。
