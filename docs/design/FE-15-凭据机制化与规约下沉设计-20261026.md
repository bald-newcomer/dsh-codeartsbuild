## 2. 设计方案（逐条）

### 2.1 P0/P1：repo_push 凭据机制化（private-token 注入 + 认证预检）

**现状**：`repo_push` 无 accessToken 参数，模型用宿主命令拼 URL（`oauth2:`/裸 token/AK:SK 均被拒）。

**设计**（来源链 + 注入 + 预检，三层）：

1. **accessToken 来源链**（优先级从高到低）：
   - 显式 `accessToken` 入参
   - 环境变量 `CAB_CODEARTSREPO_TOKEN`
   - `.dsh-codearts` 文件的 `CAB_CODEARTSREPO_TOKEN` 键（key=value 行，复用 `loadFileEnv`）

2. **凭据注入**（不落盘）：
   - 有 accessToken 时，构造 `https://private-token:<TOKEN>@codehub...` push URL
   - 通过 `git -c remote.origin.url=<authedUrl>` 进程级覆盖（**不写 .git/config、不改 origin、不进输出**）
   - token 绝不出现在工具输出中（防泄露）

3. **认证预检**（无 accessToken 时）：
   - 探测本地凭据：remote URL 是否已内嵌 `user:pass` / `credential.helper` 是否已配置
   - 均无 → 返回 `reason:missing_credentials` 引导用户提供，**不盲目撞 AUTH**

**落点**：`src/providers/codeartsbuild/repo-push.ts`（`resolveAccessToken`/`buildAuthedUrl`/`hasLocalCredential`/`urlHasEmbeddedCredentials`）

**补充（2026-10-28，会话 1d8dc38a）：新增 `codeartsbuild_get_push_credential` 工具（§2.19）**

问题：`repo_push` 失败后模型转宿主命令（pwsh）手动推送时，无法复用已配置令牌，遂自行拼 URL（`oauth2:`/裸 token/`AK:SK` 均被拒 `CH.00905401`）。

设计：新增本地工具，`resolveAccessToken`/`buildAuthedUrl` 复用 repo-push 实现——按来源链解析令牌 → 构造 `https://private-token:<TOKEN>@codehub...` → 返回 `authed_url` + `commands`（可直接复制的 `set_url_and_push`/`direct_push`）；无令牌 → `available:false + reason:no_token` 引导。模型复制命令即可用，无需拼 URL。

**落点**：`src/providers/codeartsbuild/get-push-credential.ts`、`src/tools/parameters.ts`（`getPushCredentialParameters`）、`src/tools/index.ts`（local 注册）、契约 §2.19 + `docs/api/tools/get_push_credential.md`

### 2.2 P1：模板挑选推荐（suggestTemplateRefs）

**现状**：`resolveStep` 未匹配时只列清单，模型仍猜不准。

**设计**：新增 `suggestTemplateRefs(stepRef)` 关键词启发式推荐：

| 模型传的步骤名 | 推荐 template_id | 附加说明 |
|---------------|-----------------|---------|
| `code-checkout`/`clone` | **无（空建议）** | 建仓+推码已完成，无需 checkout 步骤 |
| `pip-install`/`requirements` | `shell-command`/`pyinstaller-build` | Python 依赖用 shell-command |
| `npm-install`/`yarn` | `npm-build` | — |
| 含 `install/deps` | `shell-command` | 自定义安装命令 |
| 含 `docker/image` | `build-image-swr` | — |
| 含 `test/unit` | `unit-report` | — |
| 含 `upload/release/obs` | `upload-release`/`upload-obs` | — |

推荐进入 `resolveStep` 报错的 **message**（非 details），因为 create_job 的 `validateStepsPlanRefs` 只透出 message。

**落点**：`src/providers/codeartsbuild/template-assembler.ts`（`STEP_NAME_SUGGESTIONS`/`suggestTemplateRefs`/`resolveStep`）

### 2.3 P2：规约下沉评估与机制化（3 项）

评估 SKILL 14 条规约，识别哪些可从"纯规约"下沉为"工具机制"：

| 规约 | 下沉处置 |
|------|---------|
| **#10 任务名查重** | ✅ 机制化：`create_job` 创建前自查 `list_jobs(search=jobName)`，命中同名 → E_PARAM 引导（复用/改名/update_job） |
| **#3 delete_job 确认** | ✅ 机制化：新增 `confirm` 参数，缺省返回 `need_confirmation` 不删除 |

### 2.4 SKILL 规约精简（删行为约束，留参数引导）

机制化后，规约中的"行为约束"部分已冗余（工具硬拦），但"参数引导"仍需保留（模型需知道参数怎么填）：

- 删 #3 "不得绕过 confirm"（机制已硬拦）
- 删 #9 "禁止自行用宿主命令拼凭据 URL"（机制已使其无意义）
- 删 #10 "模型侧无需再手动查重"（工具自动查重）
- 保留 #12 "镜像字面量照抄"（参数填写指导）
- 保留 #13 "模型应主动带 projectId"（减少兜底开销）
- 意图 1 流程图删 `list_jobs(search=任务名) 查重` 步骤（工具自动查重）

**落点**：`skills/codeartsbuild/SKILL.md`（规约标注【机制化】/【机制化-参数引导】）

## 4. 验证方式

1. 257 测试全绿 + tsc 通过（已验证，2026-10-30 复跑）。
2. 凭据注入：提供 accessToken → push 命令含 `remote.origin.url=https://private-token:TOKEN@...`，输出不含 token（防泄露）。
3. 认证预检：无 accessToken + 无本地凭据 → `reason:missing_credentials`，不触发 push。

5. 模板推荐：`pip-install` → 推荐 `shell-command, pyinstaller-build`；`code-checkout` → 提示无需 checkout。
6. 任务名查重：命中同名 → E_PARAM 引导复用/改名。
7. delete_job 确认：缺省 → `need_confirmation` 不删除。
8. `get_push_credential`（2026-10-28）：显式/env/`.dsh-codearts` 三种来源均返回 `private-token` authedUrl；无令牌 → `reason:no_token`（7 用例覆盖）。
