## 0. 文档定位

对 `codeartsbuild` provider 下**冗长、内联逻辑多、可读性差**的 handler 做**纯结构重构**：提取辅助函数、压缩 handler 主干，**零行为变更**（不改任何返回字段/文案/错误码/调用序列）。本文档记录重构设计与实施，供后续审查与回归对照。

---

## 1. 问题背景

`repo-prepare.ts`（352 行）被用户点名"冗长且阅读体验差"。审查发现同类问题存在于多个 handler：

| 文件 | 行数 | 冗长点 |
|------|------|--------|
| `repo-prepare.ts` | 352 | handler 内联三大分支；mismatch 警告合并 / scmHint / 建仓 base 组装**三处重复** |
| `wait-build.ts` | 182 | 轮询循环内联 20+ 行网络重试 + 12 行状态复核 |
| `create-job.ts` | 217 | 校验段（jobName/flavor）与 422 增强错误内联在 handler |
| `template-assembler.ts` | 242 | 数据驱动小函数集合，**已清晰，无需动** |
| `list-artifacts.ts` / `list-records.ts` | 113/107 | "校验→直通HTTP→规范化→返回"同构小文件，**无需动** |

**重构原则**（本特性核心约束）：
1. **零行为变更**——所有返回字段、提示文案、错误码、HTTP 调用序列、轮询节奏逐字保持；单测**原样通过（零修改）**为硬性验收。
2. **提取不引入新抽象**——只把内联逻辑挪进具名函数，不新增配置/依赖/类型。
3. **handler 主干只留骨架**——校验、编排、返回一目了然。

## 2. 重构设计

### 2.1 `repo-prepare.ts`（352 → 326 行）

handler 内联三大分支（无远端建仓 / 已有远端命中 / 已有远端未命中建仓），mismatch 警告合并、scmHint、建仓 base 组装三处重复。提取 6 个辅助函数：

| 函数 | 提取的内联逻辑 | 复用点 |
|------|---------------|--------|
| `detectRemote` | ② git remote -v 检测（原 15 行 try/catch） | 1 |
| `lookupRepoInProject` | ③.2 per-project 按名查 + 回读 repoId（原 30 行循环改 `list.find`） | 1 |
| `buildCreatedBase` | 建仓结果 base 组装 | 2（无远端 + 未命中建仓） |
| `applyMismatchWarning` | mismatch 警告合并 + 消息后缀（原内联 `Object.assign` + 三元） | 2（created/existing 场景） |
| `buildScmHint` | scmHint 字符串 | 3 |
| `buildMismatchWarning` | 警告字段构造 | 由 applyMismatchWarning 调用 |

关键行为保持点：
- `lookupRepoInProject` 查询失败**吞异常返回 null**（原 `catch {}` 语义）——未命中 → 建仓兜底，不阻断。
- 建仓轮询（10s 上限、CH.000404 容错）原样保留。

### 2.1.1 第二轮评审细化（2026-10-08 补充）

针对用户第二轮评审意见（方法过长 / if 阅读性 / 内联 base / 文案措辞）追加：

| 意见 | 处理 | 新函数/改动 |
|------|------|------------|
| `createRepoInProject` 过长（105 行） | 轮询部分拆出为独立函数 | `pollRepositoryInfo`（每 1s 一次，最长 10 次；404 未初始化视为等待） |
| if 条件阅读性差（双重否定 `if (!(e instanceof ToolException && ...))`） | 改写为正向可读判断 | `isInitPending404`（CH.000404/仓库不存在 → 未初始化，不视为失败） |
| handler 内内联 `const base`（命中已有仓库分支） | 提取为具名构造函数，与 `buildCreatedBase` 对称 | `buildExistingBase(found, repoName, existingRemote, branch)` |
| 323 行文案 `推送代码请执行:` | 措辞改为命令参考（非强制指令） | → `推送代码参考执行命令:` |

行为保持：`pollRepositoryInfo` 轮询节奏/404 容错与原内联逐字等价；`isInitPending404` 判定逻辑与原嵌套条件等价（返回类型用 `NonNullable<GetRepositoryResponse['result']>` 修复 TS2339）；`buildExistingBase` 字段与原字面量逐字一致（测试断言字段不受影响）。

### 2.2 `wait-build.ts`（轮询循环瘦身 ~55 行）

handler 轮询循环内联 20+ 行网络重试 + 12 行状态复核。提取 2 个纯函数：

| 函数 | 提取的内联逻辑 | 行为保持 |
|------|---------------|---------|
| `fetchStatusWithRetry` | 单次查询网络抖动重试 ≤2 次（间隔 2s）+ 非网络错误（E_AUTH/E_PARAM）透传 | 重试节奏、错误分类逐字等价 |
| `mapStatusWithVerify` | 状态映射（mapWorkflowStatus）+ completed+error 时 record-info 复核 | 复核时序不变（同轮发生） |

轮询循环只剩骨架：`查询 → 失败退避/成功映射 → 终态返回 → 退避继续`。网络失败连续 3 轮抛 E_NETWORK、退避 ×1.5、TIMEOUT 非异常返回全部保持。

### 2.3 `create-job.ts`（handler 主干 ~90 → ~55 行）

| 函数 | 提取的内联逻辑 | 说明 |
|------|---------------|------|
| `validateJobBasics` | jobName 长度/字符集 + flavor 枚举校验 | **返回解析后 flavor**（`flavor ?? 'DEFAULT'`），handler 直接使用，修复提取时的作用域丢失 |
| `buildScmsEmptyHint` | 空 scms 附加提示（FE-09 P2-C） | 原内联 if/三元 |
| `enhanceScmTracebackError` | 422 仓库不存在回溯提示（FE-07 §2.5） | 原 catch 内 10 行 |
