## 0. 文档定位

e3c9f738 会话（2026-11-02）暴露 FE-13/14/15 修复后仍存在的 4 类问题：

1. **推码分支决策**：模型在 pwsh 中误用 `git reset --hard`/`git push -f`（违反规约 #11 软约束）；远端有初始提交时 `pull --rebase` 撞 README 冲突，模型 abort 后强推撞 master 受保护
2. **step 字段名错误**：shell-command 模块认 `properties.command`，模型前 2 次用 `shellContent`（被服务端静默吞掉变 `echo 'hello'`）——`validateSteps` 只校验 module_id + image，不校验 properties 键名
3. **image 字面量来源**：`shell4.2.46-git1.8.3-zip6.00` 虽然合法（在 shell-command 的 image_select 中），但模型未从 list_templates/get_job 验证即使用——本次恰好命中，下次可能臆造不存在的 image
4. **language 速选命中差**：模型传 `language: ""`（空）跳过速选，凭探测猜命令；无完全匹配时无模糊匹配机制，模型不知道选最相近的（如 `Python/uv` → `Python/其他（setuptools 等）`）

本文档设计这 4 类修复，**核心思路是字段契约机制化 + 分支预检硬约束 + image 来源软引导 + language 模糊匹配**。

> **2026-11-03 设计调整**：
> - **取消 subagent 前置软引导**：FE-14 subagent 前置保持 SKILL 规约约束，不在 create_job 加 buildInfoSource 机制化（用户决策：不强制）
> - **P2 改为 language 速选模糊匹配机制化**：不新增 `Python/uv` 组合，改为 language 速选无完全匹配时挑最相近的（前缀/包含匹配），找不到时返回 `need_language_choice` + 可用语言列表让用户选

## 2. 设计方案（逐条）

### 2.1 P0：step 字段契约机制化（properties 键名校验）

**现状**：`validateSteps` 只校验 `module_id` 白名单 + `image` 可用值，**不校验 `properties` 键名**——模型传 `shellContent`（不在 shell-command 模板 properties 中）被服务端静默吞掉变 `echo 'hello'`。

**设计**：

1. **加载模板 properties 键名白名单**：从 `step-templates.json` 的每个模板 `properties` 中提取键名集合（剔除 `_select` 后缀字段），形成 `TEMPLATE_ALLOWED_PROPERTY_KEYS: Map<module_id, Set<string>>`。

2. **`validateStepProperties(index, step)`**：校验 `step.properties` 的每个键必须在模板白名单中，否则 E_PARAM 引导：
   - 键 `shellContent` 不在 shell-command 模板（`{command, preCondition, image, image_select}`）→ E_PARAM
   - 错误信息列出模板可用键名 + 推荐正确字段名（前缀匹配：`shellContent` → 推荐最近字段名）
   - 软提示：`shellContent` 在 stepsPlan 语法中是合法字段名（`stepsPlan[].properties.shellContent`），但 `steps[].properties` 用 `command`——区分两层语法

3. **注入点**：`validateSteps` 内，`validateStepImage` 之后追加 `validateStepProperties`。

**落点**：`src/providers/codeartsbuild/template-assembler.ts`（`TEMPLATE_ALLOWED_PROPERTY_KEYS` + `validateStepProperties` + 模糊推荐 `suggestClosestPropertyKey`）

### 2.2 P1：image 字面量来源校验

**现状**：`validateStepImage` 已校验 image 在 `image_select` 枚举内（FE-11），但**不校验来源**——模型可凭记忆传合法值。本次恰好命中 `shell4.2.46-git1.8.3-zip6.00`，下次可能臆造。

**设计**（软引导）：

1. **create_job 入参新增 `imageSource?: 'list_templates' | 'get_job' | 'default' | 'manual'`**：
   - `'list_templates'`/`'get_job'`：从工具返回值取（正常路径）
   - `'default'`：用模板默认 image（省略 properties.image）
   - `'manual'`：模型凭记忆传（降级路径）
   - 未传 + properties.image 被覆盖 → 返回 `image_source_unverified` 警告（不阻断，附 next_actions 引导先 list_templates）

2. **不重复 FE-11 校验**：`validateStepImage` 已硬拦不在 image_select 中的值，本机制只补充来源引导。

**落点**：`src/providers/codeartsbuild/create-job.ts`（入参 + imageSource 检查）、`src/tools/parameters.ts`

### 2.3 P1：推码分支预检 + 受保护分支防御

**现状**：`repo_push` 的 `branch` 入参默认 `master`，不校验本地实际分支；模型在 pwsh 中用 `git reset --hard`/`push -f` 撞 master 受保护。

**设计**（两层）：

1. **`repo_push` 分支预检**（工具内机制化）：
   - 推送前 `git rev-parse --abbrev-ref HEAD` 取本地当前分支
   - 当前分支 ≠ `branch` 入参 → 返回 `branch_mismatch` 警告（不阻断，附 next_actions：确认推送 `<current>` 还是切到 `<branch>`）
   - 当前分支 = `branch` 入参 → 正常推送

2. **`repo_push` 失败分类加 `PROTECTED_BRANCH`**：
   - stderr 含 `protected`/`! [remote rejected] (protected branch)`/`cannot force push to protected` → 分类为 `PROTECTED_BRANCH`
   - next_actions：`禁止 push -f；用 git pull --rebase origin <branch> 后 push（非 -f）；或联系管理员开临时强推权限`
   - 不自动重试（-f 已被服务端拒，重试无意义）

3. **规约 #11 软约束保持**：`git reset --hard`/`push -f` 在 pwsh 中无法工具拦，保持 SKILL 规约 #11 软约束；但 `PROTECTED_BRANCH` 分类 + next_actions 让模型知道"撞受保护分支后该走 rebase 而非 -f"。

**落点**：`src/providers/codeartsbuild/repo-push.ts`（分支预检 + `PROTECTED_BRANCH` 分类 + `branch_mismatch` 返回）

### 2.4 P2：language 速选模糊匹配机制化

**现状**：`LANGUAGE_COMBINATIONS` 只有 `Python/PyInstaller`/`Python/其他（setuptools 等）` 等枚举，模型传 `Python/uv`（不在枚举）→ 直接 E_PARAM 拒绝；模型只能传空 `language` 跳过速选手拼 steps。

**设计**（模糊匹配 + 用户选择兜底）：

1. **`resolveLanguage` 三层匹配**：
   - **完全匹配**：`Python/uv` === 枚举键 → 直接用（现状）
   - **前缀匹配**：`Python/uv` 前缀 `Python/` → 找到 `Python/其他（setuptools 等）`（最相近的 Python 通用组合）→ 用之并标注 `language_matched_by: 'prefix'`
   - **包含匹配**：`uv Python` 包含 `Python` → 同上
   - **无匹配** → 返回 `need_language_choice` + 可用语言列表（不阻断，让用户/模型从列表选）

2. **匹配优先级**：完全 > 前缀 > 包含 > 无匹配（让用户选）。

3. **`Python/uv` 命中 `Python/其他（setuptools 等）`**：uv 是 Python 通用包管理器，`Python/其他` 组合是 `['shell-command', 'upload-release']`，image 默认 `shell4.2.46-git1.8.3-zip6.00`——模型按 build_info 覆盖 command 为 `uv sync && uv build` 即可。

4. **不新增 `Python/uv` 组合**：模糊匹配已让 `Python/uv` 命中 `Python/其他`，无需新增枚举（避免组合膨胀）。

**落点**：`src/providers/codeartsbuild/template-assembler.ts`（`resolveLanguage` + `suggestClosestLanguage`）

1. 单测全绿 + tsc 通过。
2. **字段契约**：`steps[0].properties.shellContent` → E_PARAM 拦截 + 推荐 `command`；`steps[0].properties.command` → 放行。

4. **分支预检**：本地当前分支 `feature/x` 但 repo_push 传 `branch: master` → `branch_mismatch` 警告 + next_actions。
5. **PROTECTED_BRANCH**：push -f 撞 master 受保护 → 分类 `PROTECTED_BRANCH` + next_actions（rebase 非 -f）。
6. **language 模糊匹配**：`language: "Python/uv"` → 前缀匹配 `Python/其他（setuptools 等）` + 标注 `language_matched_by: 'prefix'`；`language: "Rust/cargo"` 无匹配 → `need_language_choice` + 可用语言列表。
